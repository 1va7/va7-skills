# va7-voice-profile：文风校准

这套方案的核心思想是**让别人能用更好的文字表达出真实的自己**。本 skill 是这一思想的地基：在写任何一篇稿子之前，先搞清楚"这个人平时怎么说话"。

## 什么时候跑

- 新用户 onboarding 的第 4 步（由 va7-onboarding 调起）。
- 老用户积累了新语料（发了新的妙记、新文章、新口述）后主动说"更新我的文风档案"。

## 语料来源（按优先级，任意一种即可开工）

1. **飞书妙记转写稿**：`lark-cli minutes +search --as user --owner-ids me` 列出 → `lark-cli minutes +detail --as user --minute-tokens <t> --transcript --output-dir <dir>` 拉取。从转写稿里**只抽取发言人是本人的段落**（按 "名字/VA7/Speaker N" 行首识别；匿名 Speaker 时先确认哪一个是本人，通常讲自己业务的第一发言人是本人，不确定就问用户）。妙记是最真实的语料：没有修饰、没有准备、就是他脑子里的东西怎么出口的。
2. **历史写作稿/已发布内容**：飞书文档、成品内容表里的口播稿全文、公众号文章。
3. **飞书聊天记录**：本人发的消息（注意只取本人发言，不要把别人的话混进语料）。
4. **本地音视频转写**：走 va7-library 的 prepare-audio + transcribe 流程。

语料量参考：妙记 2~4 场或文章 5~10 篇即可出第一版档案；越多越准，但 3 万字以上的边际收益不大。

**拿不到任何语料时不要编造风格档案。** 明确告诉用户缺语料，请他提供任意一种。

## 分析维度

对语料做以下维度的分析，每个维度都要带**原文摘录**作为证据（没有证据的结论不写进档案）：

1. **句式结构**：平均句长、短句/长句比例、标志性句式（转折、因果、排比、反问）
2. **段落与开头模式**：他习惯怎么开场、怎么推进、怎么收尾
3. **用词习惯**：高频词、口头禅、中英混用情况、专业术语使用密度、会回避哪些词
4. **标点与排版**：标点偏好、分段密度、是否用 emoji/表情、强调方式
5. **论证方式**：习惯用个人经历、数据、引用、类比还是对比来说理
6. **语气与口吻**：人称视角、自谦/自信的姿态、和读者的距离感
7. **口语独有特征**（妙记语料才有）：语气词、停顿习惯、重复强调方式——这些是口播稿最需要的
8. **观点密度与节奏**：一段话里塞几个信息点，习惯先给结论还是先铺垫

## 产出格式

写入 `<user_dir>/writing-style-profile.md`，结构：

```markdown
# <名字> 写作风格档案

> 校准时间：YYYY-MM-DD ｜ 语料来源：N 场妙记 / M 篇文章（列出标题）
> 语料总量：约 X 万字

## 一、句式结构
（结论 + 原文证据摘录）

## 二、段落与开头模式
...

## 三、用词习惯
...

## 四、标点与排版
...

## 五、论证方式
...

## 六、语气与口吻
...

## 七、口语特征（口播用）
...

## 八、模仿要点（写给 AI 的操作指令）

写这个人的稿子时：
- （可直接执行的规则，例如：句子平均不超过 20 字；先给结论再展开；每段只讲一个点）
- ...

## 九、反例（不要这样写）
（用他的语料风格改写一段通用 AI 腔的对比示例）
```

**第八节是整份档案最重要的部分**：前面所有分析最终要落成"写稿时照着执行的操作规则"，供 va7-script 等写作 skill 直接引用。

## 更新策略

- 新语料来了：重新跑分析，**重写档案而不是追加**。档案永远反映当前最新、最完整的判断。
- 校准后在用户配置登记：`voice_profile.path`、`calibrated_at`、`corpus_sources`。

## 隐私红线

- 语料和档案只存在该用户的目录下，不进任何共享空间。
- 不要把 A 用户的语料或档案用于 B 用户。
- 档案里不要出现语料中涉及第三方隐私的内容（客户名、内部纠纷细节），只保留语言特征相关的摘录，摘录时对敏感名字做脱敏。
