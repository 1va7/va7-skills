# 每日内容早报

解决的问题：会议纪要原样堆着就是 25T 废物，定期提炼一小部分关键知识、查重、只沉淀有价值的，才是解法。人只出现在最后一道 gate。

## 流程（三个环节）

**1. 凌晨定时提炼（无人值守）**

- 拉用户昨天（本地时区）全部妙记：`lark-cli minutes +search --as user --owner-ids me`，按日期过滤后逐场拉转写稿
- 每场提炼：核心 thesis（一句话）、关键要点（2-4 条）、值得立题的判断（明确标"无"如果只是过程性讨论）
- 查重：对每个候选方向，用关键词搜用户灵感库的素材表和选题表；与已有内容实质重复的丢弃或标注"与已有 X 重叠"
- 产出早报：编号列出候选选题方向，每条一句话 thesis + 一行出处（哪场会、谁说的）+ 查重结论；没有值得入库的也明说"昨天 N 场会，无可立题内容"

**2. 早报群 human gate（早上）**

- 早报发到专门的早报群（onboarding 时创建），格式固定："昨天提炼出 N 个选题方向，要不要入库？"+ 编号列表
- 用户回复：全入库 / 都不要 / 指定编号（如"1、3 入库，2 不要"）
- 用户不回复就不动，第二天早报里附带提示上一批待决

**3. 按拍板入库**

- 入选条目走 va7-library 流程写入素材表（状态"未拆解"），选题拆解仍走 va7-pipeline 的编辑判断，不自动 1:1
- 入库后回执：每条对应的素材记录链接

## 权限前提（onboarding 时一次性拿全）

扫全部妙记、建群（im:chat）、建多维表格（bitable）、建文档。初始化时缺哪个 scope 就当场补哪个，不要等日运行时才发现。

## 部署形态

- 服务器侧：cron 定时跑"拉取+提炼（headless agent）+发送"，脚本随环境部署，不进本仓库
- 用户侧：只需在早报群里回复，零操作
- 失败兜底：提炼或发送失败时第二天早报开头注明"昨日早报缺失原因"，不静默吞掉
